# VIP Phase 5 Report Export Report

## Summary
Phase 5 implements PDF and DOCX export for `ReportDraft` records. Owners can now export a report draft from `/reports/[reportId]`, track export status, and open/download generated files from inside the app.

No email sending, approval/send flow, automatic delivery, destructive cleanup, or old report route removal was implemented.

## APIs Added
- `GET /api/reports/[reportId]/exports`
  - Returns all export records for the report and latest PDF/DOCX references.
- `POST /api/reports/[reportId]/exports`
  - Accepts `format: PDF | DOCX` and optional `forceRegenerate`.
  - Reuses the latest completed export unless regeneration is requested.
  - Generates a file from the current `ReportDraft`.
  - Updates `ReportDraft.exportStatus`, `pdfUrl`, and `docxUrl` snapshots.
  - Stores failed export status and error messages instead of faking success.

## Export Formats Supported
- PDF
- DOCX

## PDF Generation Approach
PDF generation uses the existing `@react-pdf/renderer` dependency. The server renderer creates a clean A4 client-ready report containing:
- report title
- client name
- report type
- generated/business date
- status
- summary
- ordered report sections
- missing data warnings
- `Generated by VIP` footer

## DOCX Generation Approach
DOCX generation uses the added `docx` package. This was added because no existing DOCX generator was installed, and Phase 5 requires a real Office Open XML document rather than HTML renamed as DOCX.

The DOCX renderer includes the same client-facing fields and section content as the PDF renderer.

## File Storage Path
Generated files are written under:
- `apps/web/public/generated/reports`

Public URLs use:
- `/generated/reports/<sanitized-file-name>`

## Security Decisions
- Request bodies cannot specify file paths.
- File names are sanitized.
- Generated files are confined to `public/generated/reports`.
- The service verifies resolved output paths remain inside the generated reports directory.
- Renderers output normalized report content, not raw tokens, credentials, or internal API payloads.
- Failed exports are recorded with error messages and do not produce fake download links.

## Known Limitations
- Exports are generated synchronously during the API request.
- Export templates are clean but intentionally simple.
- Approval/send and email delivery remain Phase 6.
- Report export records are app-owned and separate from old content execution reports.
- No browser smoke test was performed because a callable local browser tool was not exposed in this session.
- `npm install docx --save` reported 3 moderate vulnerabilities in the existing app dependency audit; no audit fix was run because that could introduce unrelated dependency churn.
